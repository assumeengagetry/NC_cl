## 复核现有成果

1. 使用Cisco Packet Tracer 9.0.1打开交付.pkt，检查4台逻辑设备、3条直通线；PC为192.168.1.155/24，DNS为192.168.1.198，HOST为192.168.1.200/24，网关未配置。DNS服务On，A和CNAME记录见报告图3、图14；最终PC DNS为.198。
2. 若要重复A三阶段测试，先将服务器及客户端DNS同时设为.199测正常；仅服务器改.198测故障；最后客户端DNS改.198恢复。保持HOST及A记录.200不变。同网段不需要默认网关。Simulation打开DNS响应PDU；此版本别名PDU的第二Answer块显示受限。
3. Wireshark打开最终pcapng，以`dns`筛出12个DNS帧；帧1/2、15/16是系统ping的A查询，23/24、25/26、27/28、29/30依次为四种nslookup。选择响应帧展开DNS、Answer、Authority检查；帧30应为NOERROR、Answer0、Authority SOA。
4. 以`frame.number >= 9 && frame.number <= 14`及`frame.number >= 20 && frame.number <= 22`查看重复ping窗口，仅有ICMP；川大没有Echo Reply，不能等同DNS失败。
5. 重新采集时先记录实际接口、路由和解析器。在每个域名首次ping前，以管理员身份执行`dscacheutil -flushcache`、`killall -HUP mDNSResponder`；首次和重复均执行macOS命令`ping -n -c 3 -W 1500 -t 8 域名`，重复前不清缓存。Wireshark/dumpcap先开始后执行命令。四种nslookup按报告图19上方命令统一指定223.5.5.5。网络、地址、DNS答案及帧号可能随时间变化，不应覆盖本次证据。
6. 按`phases.json`中的DNS域名和各ping实际地址过滤实验流量，保留原始字节、时间戳后合并，再依据新文件编号分析；不要沿用本轮帧号。`run_real_dns.py`、`analyze_real_dns.py`是本次采集和分析脚本存档，含本次路径与接口，复用前应另存、调整路径和当时接口，勿覆盖原成果。
7. Overleaf上传报告ZIP，选择main.tex与XeLaTeX编译；本机独立解压编译与交付PDF逐字节相同。字体替代、PDU显示限制、学时留空见交付说明。

本轮未修改DNS、VPN、路由或网络服务配置；采集已经停止。Packet Tracer临时模块已删除、脚本权限Disabled，最终工程不依赖脚本。
